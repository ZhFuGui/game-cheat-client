# v6.5：延后且有期限的连接复核候选

2026-10-21。实机仍v6.4，PC1.2.8；本候选未授权烧录，不能称故障已修复。

## 本次已知事实

用户明确“约5秒”是体感上的复现时间，没有声称固件存在5秒计时器。排查依据是停止移动后发生断开，不把5秒写成算法或验收阈值。

固定接线的Windows后台观察trial2为21:12:17—21:13:17，256条Raw Input、583份电源/光标样本，五个节点的最近电源状态均D0。用户反馈“难说”，本次首份移动手感不作通过或失败。没有独立物理起动时间；后台交付/最近电源状态不能单独证明丢包或排除短挂起。trial1没有同步发出操作提示，不作受控响应试验。

随后另开原生CDC只读3秒和8秒，不与Windows观察重叠。8秒窗口鼠标RX全程78911、82、7599不变，release273→276、init267→270；DROP时间1053836、1056453、1059067、1061678ms，循环间隔2617、2614、2611ms。此为异常后的重复周期，不是从最后一次手动移动到首次断开的门槛。NAK仍增长，HOST显式恢复/超时0、原生epoch3/cfg1保持，控制steps/synthetic0。已独立复现Host释放、重枚举路径；不能把此结论倒填成trial2的人工失败。

DROP仍为task11/bus0/MODE D1；此前MODE C9、SAMPLEBUS读值04，检查均走incomplete。v6.4源码确认为检查若干次后未见完成就立即继续busprobe，后者可关闭SOF并使USB::Task调用Release。为何最先产生SE0仍未证实；不是单凭正常NAK就调用Release。

证据在`build/idle-wakeup-followup-20261021/`，包括两个窗口的原始CSV、元数据、分析、用户上下文及两个post-trial-native日志、post-trial-result.json。

## 候选修改

只针对受支持接收器已完成初始化、已连接FS设备的CONDETIRQ且锁存线路为SE0。枚举阶段不启用协作等待，保留上游库原始连接处理，避免与枚举的阻塞传输共享HCTL：

1. 保存原事件证据，让CONDETIRQ保持待处理，保持原SOF；先让出主循环，经过100µs安静窗口再发SAMPLEBUS。
2. 后续主循环检查采样状态和线路；SE0变为非零线路是新的线路证据。J交还原全速逻辑，K/SE1仍交还原速度/错误逻辑，不强制就绪。
3. 采样明确完成且仍SE0，或总检查达到200µs期限仍无可用线路，交还原busprobe/Release。期限从第一次事件计时，不在每轮刷新；不增加delay或忙等。
4. 等待期间物理轮询和新的/待启动控制传输暂不写HCTL，避免覆盖SAMPLEBUS。已经排队的物理USB报告、UART与CDC服务继续运行。恢复/释放清除待检查状态。

100/200µs是本候选的工程参数，不是用户所说的约5秒，也不是规范给出的统一数值。期限在主循环再次服务时核验，不能当作包含所有ISR/调度延迟的实测硬上限。常态没有额外SPI事务；异常检查期间可能延后一次轮询，实际1000Hz、最大输入延迟与500Hz控制仍须硬件核验。

不调整SPI速率、引脚、描述符、FIFO、物理1ms期限、TTL500000/2ms/各轴±100/预算200、PC算法或Reader。PC1.2.8不需改版。

## 验证和边界

真实vendored驱动的同一延后采样模拟在固定v6.4上失败、新版通过；这是SPI/寄存器模拟，不是实机根因证明。回归覆盖真实SE0、卡住采样、200µs期限、晚调度、micros回绕/取消、其他IRQ保留、30000正常事件零额外SPI；HostTransport确认HCTL等待时不能被改写且队列继续提交。原控制、反馈、500Hz/1000Hz事件模型、描述符和AVR构建继续验证。静态SRAM/栈余量不是实际栈水位。

此候选验证“原检查过早退回断开”的软件处理问题，尚未证明最初SE0是瞬态误判、接收器电源行为还是硬件信号；若实机复核仍是持续SE0，就不能以延迟检查宣称修复。

参考：[MAX3421E编程指南](https://www.analog.com/media/en/technical-documentation/user-guides/max3421e-programming-guide.pdf)的CONDETIRQ和SAMPLEBUS部分；[官方Errata](https://www.analog.com/media/en/technical-documentation/data-sheets/errata_max3421e.pdf)。指南称采样完成清位，上游初始化代码却等待置位，因此保留读值并核验从锁存SE0到新线路的变化，不直接反转完成位。此次读取的rev13不符合Errata中旧版SNDFIFO问题的适用范围，未据此更改OUT逻辑。
