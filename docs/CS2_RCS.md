# CS2 Aimbot 后坐补偿

PC2.8.48 起，进入 **Aim → Aimbot → 后坐补偿**，开启「补偿发射后坐偏移」后按住原来的跟随侧键。此开关沿用已保存的 cs2RecoilCompensation，Rage 共用它。有合格目标时使用目标方向。没有合格目标时，手动鼠标输入决定瞄准方向，顶部状态栏显示「正在补偿后坐，瞄准方向由鼠标控制」。松开即停止。

独立 RCS 子页和输出程序已删除。打开旧 RCS 子页链接时跳转到 Aimbot。旧配置里的独立启用、按键、速度、年龄及响应延迟字段允许读入后丢弃。工作区沿用已保存的 Aimbot 启用、跟随侧键、速度和 Aim 常规中的采样资格、预计执行延迟与输入换算。

## 参考方向与位移账本

- 读取当前核验通过的本地预测输入方向，以 Aimbot 的 P/U 求值估计执行时刻的发射偏移。
- 设当前预测输入方向为 E，E 含按响应时间估计仍在途的已发位移。C 为当前手动瞄准阶段已接受的补偿角度总量。手动瞄准方向为 E − C + B，预测发射方向为 E + P + U。B 是启动或切换时建立的基准偏移。
- 一次新的侧键保持以当前无后坐输入方向建立基准，首个已观测的 P/U 可参与补偿。已有目标失效时，以当前预测输入与最近可信的发射偏移联结两种模式，保留原人的锁定身份。如果锁定对象复现，直接恢复它的当前目标方向，已发位移仍参与计算。
- 两种模式共用一个设备输出和在途账本。无目标时直接量化受限的剩余角差。有目标时使用已选的跟随轨迹与速度策略。提议被拒绝会回滚对应的计数额度与补偿记账。
- 普通本地输入、完整 P/U、新鲜采样、会话与物理侧键均须核验。真正的身份变化要求先松键。暂时缺数据或武器、预测时间路线发生变化后，从当前可信方向重新建立基准。目标已死亡时本次按住可继续手动补偿，松键后可重新选人。

在途位移按「预计执行延迟」记账，游戏内的输入响应仍需实测。原生回归用合成数据核验手动转向过边界、补偿回传、目标重新出现、重试和失效恢复。桌面验证覆盖导航和既有配置迁移。
