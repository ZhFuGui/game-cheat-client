# ESP 绘制前与绘制耗时

PC2.8.2。用户要求替换ESP工具栏右侧“可见/人物”计数，展示近2秒的两个平均耗时；适用于已接入的PUBG和CS2。画布内部的观看人数及绘制FPS保留。

| 指标 | 起点 | 终点 |
|---|---|---|
| 处理 | 当前实际绘制的新数据帧完整TCP记录接收QPC | 渲染线程刷新最新请求后、resize/投影/图元生成之前 |
| 绘制 | 上述绘制入口QPC | 该次成功Present所对应的D3D完成栅栏通知被观察到 |

第一段是墙钟耗时，包含解码、场景准备、该绘制帧实际依赖的分析、提交前等待以及渲染队列/背压等待，不是纯CPU占用。第二段包含投影、图元与绘制资源准备、CPU提交和GPU或WARP执行；终点包含完成事件唤醒延时，不代表显示器扫描或光子时间。不能以原projectionMs或drawMs的单帧CPU提交耗时代替它。没有完成栅栏能力或两秒内无有效新帧时显示—，真实零值保持0.00。

## 来源与作用域

domain/SourceReceipt只保存消费端本地完整接收戳及Reader/连接/会话/epoch/capture身份。CS2在既有完整记录接收分支创建独立receipt，不要求Reader时钟校准；原控制用SourceSample的存在条件、时间和资格不变。PUBG沿用2.8.1已有精确接收戳，作为consumer-only Header元数据保存；以实际绘制Living人物批次为主要帧，Local组合等待可计入第一段，不混合两通道为一个虚构Reader批次。

SceneSubmission明确携带该绘制帧的receipt。普通掩体/余伤/头伤若选取已有分析帧，必须连同该帧原receipt提交。最高伤害瞄点仍独立滞后，它完成时不能把当前基础帧或receipt换回旧输入，也不为新计时强等其当前帧结果。

## 有界统计

render/frame_clock统一本地入口与完成观察的QPC单位；计时不可用只撤销统计，不停止绘制或改变输出资格。render/frame_timing使用同一批首次成功完成绘制的新数据帧配对累计两段，各阶段样本数一致，毫秒桶保留近2000ms。每帧两段之和等于该帧接收到完成通知的时间；Reader页统计的是全部有效接收帧，两个页面的样本集合不一定相同，不把各自均值直接相加称为整体均值。

每来源最多4096个近期capture去重标识，并维护退休下界；允许分析结果导致的近期乱序首次绘制，重复重绘不把旧数据年龄变成新处理样本。换连接、会话、epoch、来源失效立即撤销历史及旧通知。GPU计时复用既有最多8张完成票据；不新增GPU等待、采样线程、绘制定时器、固定FPS上限或像素传输。

RenderStats只输出均值/样本数，RuntimeState.espTiming为严格可选DTO；EspStatus按字段订阅，仅显示两项ms及工具提示。原Reader三段和底部一秒统计不变。本次不改Reader契约、Aimbot/RCS数学、控制资格、串口和固件。

## 验证

纯计时测试覆盖配对、同批之和、近期乱序、重复重绘、过期、真零、反序/非有限值、连接/epoch切换及旧通知撤销。最高伤害阻塞测试核对新基础帧仍携带新receipt。隐藏透明硬件/WARP测试刻意在投影内延时，核对第二段包含投影且由真实完成通知收尾，无Reader时钟仍能计时；只使用自有隐藏窗口与缓冲。UI测试覆盖原计数移除、两位小数/零/未知/断连及中英文。实际证据见PROJECT_MEMORY最新条目。
