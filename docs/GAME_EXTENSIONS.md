# 游戏扩展架构与 CS2 掩体检测接入准备

2026-10-26，PC2.6.0沿用强类型宿主、ESP插槽和地图身份消费；固定traceline Provider已分别装配掩体可见性与穿透剩余伤害两个只读扩展，共用地图场景。两个开关分别保存，默认关闭。静态完整场景不包含实时门/破坏/烟雾状态；来源与二进制边界见[traceline验收](TRACELINE_ACCEPTANCE.md)，余伤语义见[穿透余伤](CS2_REMAINING_DAMAGE.md)。

用户要求各游戏可组合自己的扩展，首批为 CS2 ESP 的敌方掩体检测；可见骨点/骨段为黄色，被遮挡部分保留红色。用户进一步要求只接入 traceline 必要的公开 API 文件及其编译产物，不纳入内部实现。最后明确先通知 Reader 提供地图名，在 traceline 完成前准备本地逻辑。

## 分层

```text
已验证的游戏来源快照
    ├─ 原 Aimbot / 独立 RCS → 现有唯一设备所有者
    └─ 游戏扩展 Host<该游戏的 Frame>
         └─ 当前游戏的只读分析扩展
              └─ 注入的几何查询端口
                   └─ traceline 二进制适配器（固定API/DLL/缓存）
         ↓ 不可变结果 + 原始快照 + 来源采样身份
       游戏投影 → 通用图元/装饰批次 → 原生 DirectX

React 扩展插槽 ← 有界扩展状态 DTO
React 控件 → 带游戏上下文的命名空间设置键
```

通用宿主只管注册、配置开关、取消、队列、结果及生命周期，不认识 CS2/PUBG、DLL、骨骼、颜色或串口。每个游戏使用自己的强类型快照，禁止把第二款游戏转换成 PUBG Frame。只读扩展不持有 Reader、鼠标或输出设备端口；现有 Aimbot/RCS 保留自身的实时控制状态机，不放入几何分析线程，也不因新扩展改动其算法。

当前实现的是“快照分析”扩展通道。未来需要贡献控制器的插件应通过独立 OutputProgram/输出模式装配点声明能力和互斥关系，不能借可视分析扩展绕过单一输出所有者。前端可增加自身的懒加载面板；当前首批已接通 ESP 设置插槽，其他页面插槽按实际功能添加。

新增同游戏扩展时新增自己的目录和面板，在本游戏 registry/界面描述符登记；不向各个页面、Reader 客户端、DirectX 或通用宿主添加游戏分支。新增游戏则提供自己的 Frame、模块和对应扩展注册。首版按实际需要实现这些挂点，不引入任意脚本执行、自动扫描 DLL 或无类型全局事件总线。

## 二进制边界

traceline正式接入采用版本固定、相互配套的交付包：

- 公开 C API 声明及其必需类型头；当前上游为 `api.h` / `types.h`，最终以正式交付为准。
- 编译好的 Windows x64 DLL，以及版本/ABI/摘要清单。
- 明确地图标识、来源和覆盖范围的离线碰撞场景及目录清单。

本项目不复制 traceline 的 `src/geometry`、`src/bvh`、`src/trace`、解析器或其他内部逻辑，不引用它的 `.vcxproj`、源码和旧静态库。正式 VS 仍为 core/native 两项目，本地测试为三个。

实际 DLL 加载、导出函数表、ABI/结构大小检查、UTF-8 路径、状态码→Unknown、场景 RAII 和释放都归适配器。适配器只以端口对游戏模块提供查询；发布时使用包内明确路径，运行不依赖 `G:\cs2-external-autowall` 开发目录。DLL 存活期必须覆盖全部场景和查询，先结束任务/释放场景再卸载。替换提供者时修改 composition 注册，不改骨段算法和 GPU。

composition在CS2工厂装配实际Provider，根目录取原生宿主旁的`data/games/cs2/cover`，不存在上游开发目录回退。Provider仅在扩展线程第一次需要场景时读取清单、核验DLL摘要与ABI并加载；清单按正式地图名称与资源标识同时匹配，拒绝默认地图和目录越界。每次场景加载核验完整文件摘要、长度、指纹、几何计数和flags；未知地图、缺文件、错误ABI或损坏均显式失败。场景通过共享API所有者保证DLL存活，最后一次场景查询结束后先销毁场景再卸载DLL。

当前资源只包含固定DLL、生成清单和27个`.cs2tl`转换缓存（24图默认完整场景及3个明确排除可破坏来源的变体）。本轮正式功能只选择intact，不能用忽略变体猜测实时破坏状态。不包含KV3/VPK或内部源码；文件后缀按上游用户最新决定统一为`.cs2tl`，底层仍为AABB BVH/CS2TLBVH v1/v2。

必要公开头及锁定清单在`third_party/traceline`，完整运行资源在`data/games/cs2/cover`。暂存工具只接显式产物和已审阅摘要；构建核验API/DLL，打包前逐缓存核验。发布资源直接放入包内native数据目录，离线运行不依赖Node、上游工程或原地图路径。

## 地图与来源一致性

Reader已经交付并配对启用`World.map_identity=13`与`Hello.map_identity=12`，冻结摘要为`12883573c8002e668bc7323c50b6cd61260387d01204267c4f3402818eff8038`。AVAILABLE=1且generation非零、名称/资源路径均存在且非空才可用；其他状态禁止携带名称/路径，包括显式空串。资源路径是引擎资源标识，不能直接作为本机地图文件路径。协议、SDK和官方37条合成记录均按交付摘要固定。

消费端使用 Reader 实例、时钟域、进程、epoch、地图名/资源路径、地图 generation 共同隔离任务。同名地图新代次同样清场景和旧结果。未知、过渡、读取失败、缺组或断开都不继承上张地图，READY/Heartbeat不复活旧值。generation是Reader观察到的变更代次，不能保证识别完全发生在两次观察之间的同名退出重进。

消费者完成全部验证后，旧PC正常退出，Reader窗口自行正常替换重启，再启动PC2.4.0。启动实收de_dust2/maps/de_dust2.vpk/generation1、70Hz，来源/时钟有效。地图身份不加入原Aimbot/RCS资格门禁；地图可读不代表离线场景已可用，两类状态分别展示。手动切图、同名实机重进与真实几何效果仍待验收。

## ESP 规则

1. 只在本批本地 team 为 2/3、对方为另一有效队伍、不是自己、非已知死亡/休眠并且骨架已核验时检测。未知关系不当敌人，队友不染黄。
2. 原点取当前本批 Reader 的视点世界坐标，不拿屏幕中心、己方脚部、旧眼部或目标坐标补缺。
3. 三态 `Visible / Occluded / Unknown`。只有成功且明确可见才黄，已遮挡红；未知沿用原色并报告缺项/错误，不宣称已经确认遮挡。名字、距离、方位环、HUD和普通标记保持原行为。
4. 每条 Reader 显式骨段检查内部采样点，不能只用整个人、头部或两端的单一布尔值。首版以16等分和6次有界转变细化生成世界线段区间；边界未确定的小区间保持 Unknown。
5. 这属于有限分辨率的射线采样，不是像素精确的遮挡轮廓；窄于采样间隔且落在探测点之间的遮挡可能漏检。将来二进制提供直接区间/批量查询时，在几何端口/采样模块替换，不扩散到页面与GPU。
6. 部分骨段先按三维参数生成端点，再用原矩阵投影、分别求每端线宽；不能线性插值屏幕坐标。骨点半径、线宽和黑描边沿用既有真实视觉缩放，文字仍用缓和曲线。
7. 基础敌我/选中分组与附加几何着色分离，黄色使用通用装饰批次，不抢占目标高亮槽位。

掩体检测本身表示加载几何的遮挡。独立remaining-damage扩展经shot_prediction端口调用新API计算剩余弹头伤害，不把可见性布尔值扩张为伤害；实际玩家扣血仍未加入。碰撞场景覆盖范围由交付清单说明，不能把只有world_physics的输入宣传为全部实体碰撞，也不推断烟雾或未知动态状态。

## 执行与生命周期

- 每个当前游戏的分析宿主拥有一个执行线程、一个最新待处理槽和一个完成结果；最多32个已登记扩展。不会积累每帧历史。
- Reader 与 Aimbot/RCS 不等待几何调用。普通新帧只替换尚未执行的输入，不反复取消正在计算的同地图任务，否则持续数据到来可能永远得不到结果。
- 切图、配置变更、断开、切换游戏、隐藏 ESP 或关闭时递增代次、取消旧任务，清掉公开结果；晚完成的任务无法重新发布。单次不可取消的DLL调用只能在返回后丢弃结果，不承诺中途终止第三方内部函数。
- 只有 ESP 可见时提交分析；最小化/隐藏暂停可视分析，不撤销正常侧键待命。关闭会话仍通过已有路径停止控制。
- 扩展结果携带其原始不可变快照及 SourceSample。颜色不能贴到更新的人物姿态/矩阵上；短时采用已分析的完整帧，并按该原样本统计GPU完成延迟。超过250ms的本机接收年龄不展示旧着色，恢复原有实时绘制。
- 每批最多16,384条射线、64个敌方对象、每人128点/256条显式边；预算耗尽或错误返回 Unknown。未知部分不染黄，状态可降级，队列与内存不随运行时间增长。
- 场景加载失败在同地图代次内按5秒重试，避免每帧反复打开坏文件；恢复、开关重置或新地图代次及时撤销旧错误。
- 普通扩展维持原共享串行组。2.8.0只将最高伤害瞄点设为独立执行组：`independentWorker()`声明自己的有界最新槽/工作线程，`maximumResultAgeMs()`声明完成结果的展示年龄；由宿主`latestFor(id,scope,now)`读取，不抢占普通组。错误仍各自捕获，不关闭Reader、Aimbot或RCS，不为每个人物/骨点创建线程。最高伤害允许1000ms内结果滞后，投影骨局部种子到当前姿态，不改变基础帧；其他扩展仍遵循上一条原capture/250ms规则。见CS2_BEST_DAMAGE.md。

## 配置与界面

首个稳定ID为 `cs2.cover-detection`，开关为 `extension.cs2.cover-detection.enabled`，默认 false。参数在游戏自己的 registry/schema 注册，按原单游戏配置存储；通用配置服务不硬编码这个插件，旧文件缺失由本游戏显式兼容。之后的插件也使用命名空间键，不侵占公共 `speed`/`trigger`。

UI按游戏描述符提供懒加载插槽，首批放在CS2 ESP设置中。只接收有界状态、原因、capture字符串及汇总计数，不传逐点/逐射线结果。等待地图、等待二进制、缺视点、缺敌我关系、场景不可用、部分未知分别可见。页面上下文栏展示当前扩展故障，使用稳定ID去重，恢复或关闭后立即撤销，不混入硬件三个圆点。
