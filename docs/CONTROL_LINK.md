# 控制链路与速度档位

PC1.2.8 / 固件v7，更新2026-10-22。PC自动识别已支持的v4/v5/v6能力链路；v7沿用v6的正式能力映射，速度档位按识别到的能力比例计算。设备实际固件版本以发布目录中的deployment.json和最新交接记录为准。

## 配套参数

| 参数 | v6/v7能力 | v5能力 | v4能力 |
| --- | --- | --- | --- |
| USB-TTL / Serial1 | 500000 baud，8N1 | 115200 baud，8N1 | 115200 baud，8N1 |
| 固件最小控制间隔 | 2ms，最多500次/秒 | 5ms，最多200次/秒 | 5ms，最多200次/秒 |
| 每份 MOTION 的 X/Y 各轴范围 | -100～100计数 | -16～16计数 | -4～4计数 |
| 单个有限会话 XY 绝对值总预算 | 最多200计数 | 最多64计数 | 最多64计数 |
| 一次修正 | START + MOTION，共48字节 | 相同 | 相同 |
| 物理接收器轮询 / HID 输出间隔 | 保持1ms | 1ms | 1ms |

共享线格式统一为 `mousebox-firmware/protocol/include/control_wire.h`，只定义帧布局与协议语义。固件能力由 `targets/<目标>/target.json` 生成，PC 仍经设备握手明确适配，不直接依赖某目标的能力文件。SerialPort只接受调用者指定的波特率，平台层不依赖盒子协议。原生USB的CDC维护口不属于TTL控制链路；v7无周期CDC诊断输出。

设备层ConnectionProbe按115200、500000依次进行无位移探测，每个速率最多等待300ms；只发送STOP及开启回传的PROBE。切速时清串口缓存、解析器及序号历史；必须获得CRC有效、序号前进、能力一致且跨至少10ms的两份回传，才确认连接并启动收发工作线程。缺失/损坏/重复或仅同批缓存的帧不能确认波特率，取消与失败有界，不会静默选一个默认速率继续发位移。外层自动重试仍为5秒。

旧回传只公布ExtendedMotion/HighRateMotion能力标志，没有完整数字参数，因此目前由ButtonObservation在单一适配入口映射上述能力。将来增加新速率或新能力版本时扩展该适配入口；若以后提供数值能力报文，可直接投影为DeviceMotionLimits。控制算法和Web不再维护按固件版本复制的速度表，也不声称能猜出未知固件的任意波特率或计数范围。

每次修正的START预算精确等于 `|dx|+|dy|`，不是200计数的固定持续运动许可。`(100,-100)`恰好使用200预算，正常一次USB提交后耗尽。20ms许可、STOP优先、物理侧键本地松键门控、重连后先松开再按和USB背压后不补发历史突发等规则保持。USB合成发生轴饱和时仍只扣实际合成量，剩余量受同一有限预算与许可约束。

500000/8N1每字节20µs。每次48字节在线占用960µs；满500次/秒时为24000字节/秒，占下行48%。这是线路计算，并非Windows、USB-TTL或真实控制频率的实测。按钮回传使用全双工的反方向，常规20ms心跳、变化最多100Hz，不逐控制帧回执。

## 五档

稳定ID、名称和已保存的选择保持，速度档位保存的是比例而非某版固件的绝对速度。设固件各轴上限为C、总预算为B、固件最小间隔为T，则：

```text
有效轴上限 = min(C, floor(B / 2))
线路间隔 = ceil(48 × 10 × 1000 / 已识别波特率) ms
有效间隔 = max(T, 线路间隔)
最大速度 = 有效轴上限 × 1000 / 有效间隔
档位速度 = 最大速度 × 档位比例
单步上限 = ceil(档位速度 × 有效间隔 / 1000)，再限制到有效轴上限
```

| 档位 | 比例 | v4计数/秒 | v5计数/秒 | v6计数/秒 |
| --- | ---: | ---: | ---: | ---: |
| 最慢 | 18.75% | 150 | 600 | 9375 |
| 较慢 | 25% | 200 | 800 | 12500 |
| 正常 | 50% | 400 | 1600 | 25000 |
| 较快 | 75% | 600 | 2400 | 37500 |
| 最快 | 100% | 800 | 3200 | 50000 |

加速度与jerk同样由当前最大速度乘档位系数得出，保持已有起停时间尺度。v5五档每轴单步为3/4/8/12/16，v6为19/25/50/75/100。若某个具有2ms/100计数能力的设备实际连接在115200，其有效间隔会自动放宽到5ms，上限为20000计数/秒，不会照搬50000。算法参数的数值校验依据16位轴/预算线格式及已验证的调度范围，不以某版固件的100/200作为全局上限。

数值来自control::speedPolicy(preset, DeviceMotionLimits)。Web下拉框同时显示比例和当前计数/秒，设置表还显示单步与加速度，原生speedPresets变更事件直接更新显示；未识别盒子时明确显示v5参考值，不能冒充已连接设备能力。它们是允许的上限；实际位移仍受目标误差、灵敏度、FOV、整数化、轨迹起停和串口忙影响。已启用的人类速度模型仍按原始拟合速度限制主动接近，不将用户采样人为放大。

缺少相机/目标几何而无法预测待生效鼠标位移的旧角差分支，增益统一限制为最多3/s。高上限暴露了该分支在80ms延迟、大角差时的重复过冲，不能把这类旧误差当成当前完整几何反复高速纠正。此限制不施加到具备几何/反馈的Ruckig接近和原生锁定纠偏。

## 物理透传隔离与兼容

物理报告保留独立FIFO、完整按钮/滚轮/厂商字段和1ms轮询；不逐包经过PC、JS或控制队列，不以合并物理报告提高控制吞吐。固件先服务Host与物理队列，再处理有界UART：每轮最多32字节，100µs检查预算，完整帧末尾的CRC/命令校验是有界尾部，因此不是“整个服务严格小于100µs”的承诺。UART满时保留未读字节；按钮回传必须有整帧空间才写出，不等待。

PC写线程将相邻START/MOTION组为一次48字节写入，减少两次独立USB-TTL写操作的开销；不等待凑批、不积累未来位移，STOP仍撤销尚未写出的修正。正在写出的完整批次不能由队列中的STOP撤回，物理侧键本地门控和许可仍有效。

v6回传新增能力位HighRateMotion=8，并同时声明ExtendedMotion=4；PC只有在回传新鲜且能力完整时才允许对应步幅/间隔。v5被识别为±16/5ms，v4为±4/5ms，不把当前固件构建常量误当作已连接设备能力。每份单步的间隔/预算由当前能力生成；普通命令入队及最终写出都复核设备上限。运行中能力变化先STOP并重建控制器，要求松键后重按，过期回传继续撤销输出。PC1.2.3曾要求配套升级的限制不再适用于PC1.2.4；本轮没有重新构建或烧录固件。

## 验证范围

固件离线覆盖40400组非零XY、2ms间隔、有限预算、许可/序号/STOP、满UART、按钮释放及USB背压。事件模型按500000/8N1逐字节送入原入口，2秒内同时送入1000个控制对与2000份物理报告，检查计数、顺序及所有非XY字节；另测试7ms USB暂停后恢复，以及UART每轮字节/时间预算。

以上v6固件事件模型使用模拟接收耗时与USB时间，不能代替ATmega32u4实际执行时间、串口USB分包、长期运行、栈水位和真实1000Hz测量。本轮PC适配新增无设备握手/能力/公式/预算回归，覆盖v4/v5/v6及模拟32/256计数能力、慢线路降频、坏帧/重复/切速缓存、同批旧帧和超时；v5与v6各五档都检查实际规划输出间隔和每秒计数上限。最新完整构建、发布与验证记录见PROJECT_MEMORY.md。物理透传固件保持原样，不将此次PC离线验证作为新的实际1000Hz保证。
