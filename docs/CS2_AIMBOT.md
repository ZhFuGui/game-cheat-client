# CS2 控制器与 Aimbot 页

## Hitbox 瞄点

在 Aim → Aimbot → CS2 跟随设置的「Hitbox 瞄点」中调整切换间隔和分布，默认 150 ms、体积均匀。切换间隔允许 1–5000 ms。内缩比例在 Aim → 常规 → 运行条件中设定，三种模式共用，范围 0–90%，新配置默认 10%。

| 分布 | 含义 |
| --- | --- |
| 体积均匀 | 同样大小的体积有相同取点概率。胶囊内的圆柱体和两端半球按各自的体积取权重 |
| 偏中心 | 沿中心到边界的射线将取样更多集中在内层 |
| 偏外层 | 提高靠近内缩边界的区域权重 |
| 中层带 | 在沿射线从中心到内缩边界的 40%–80% 之间均匀取体积样本 |

按枪械类别解析的头、颈、胸、腹、骨盆分别对应已核验 cstrike 资源的 head_0 / neck_0 / spine_3 / spine_0 / pelvis。胸部对应原上胸选择。取样与缩小盒体、胶囊半径、球体半径使用统一几何。本地点随本批骨姿态旋转、缩放和移动。姿态无效时暂停目标跟随，已有锁定在姿态恢复时继续。换枪选到新部位时即刻切到对应命中体并重新计时。

PC2.8.50 开启掩体判断后，每次抽样沿用所选分布，拒绝当前预测射线路径被静态掩体遮挡的样本。首选时每个合格候选人最多抽 3 次，锁定后每轮最多复查旧点并抽 8 次。旧点可见时在换点到期前继续使用，到期后在新点通过检查前也可沿用。旧点被挡可提前换点。没有通过检查的瞄点时暂停目标跟随，保留当前锁定和部位，后续控制轮继续找，接受新点时重新计时。查询只验证单条射线，有限次拒绝显示为「正在寻找露出的 Hitbox 瞄点」。仅露出很小一部分时可能需要多轮，中层带只覆盖设定的径向范围。状态读取和提交复核只检查已接受点。关闭掩体判断时按原间隔换点。

以下旧版本章节中提到的单一语义骨点，记录的是 Hitbox 瞄点接入前的选点方式。

PC2.8.48 新增 [Aimbot 手动方向的后坐补偿](CS2_RCS.md)。没有目标时可以按住跟随侧键补偿后坐。现有开关位于 Aimbot 的后坐补偿设置，启用后在跟随与手动方向之间切换。下面关于暂停与恢复的目标规则仍用于目标跟随。

PC2.2.6，2026-10-24。使用最终冻结的 Reader v1/0dd 与 Build 14192 原生求值器。默认使用明确标注“未实测”的原生1:1公式，设备计数校准为可选验证；选择实测模式时才要求有效记录。公式假设与硬件实测分开，真实游戏手感仍需用户验收。

按游戏保存的算法模式：v1固定PC2.2.4，v2为后坐差分快速通道，v3为完整残差直接量化，v4为全局输入方向加P/U与v1运动。另有16个单变量组固定完整v1资格和目标，只改变登记的一项计算。旧数据默认v1，用户手动比较。下述公式描述共享基础及v1；v4明确移除原生眼角资格/响应依赖，不能误套下文原生角门禁。各版实际字段与假设见[算法版本](AIMBOT_VERSIONS.md)，模块拆分见[计算流水线](CS2_CONTROL_PIPELINE.md)。

## 模块边界

2026-11-14：Aimbot 新增按手持枪械类别保存的瞄准部位。手枪 `cs2AimPartPistol=0`（头），步枪 `cs2AimPartRifle=1` 与冲锋枪 `cs2AimPartSmg=1`（颈），狙击枪 `cs2AimPartSniper=2`（胸）；每类可独立选择头/颈/胸/腹/骨盆，`-1` 表示沿用原 `cs2AimPart` 默认部位。狙击枪包括 AWP、SSG 08、G3SG1 和 SCAR-20。霰弹枪、机枪、未知或缺失武器资料使用原默认部位，不按武器名称猜测，也不沿用上一把枪的类别。旧配置仅补充缺失的四个默认值，保留原默认部位、已有参数与记录。

`model/weapon_category.hpp` 集中维护已核验的 34 项枪械编号分类，Triggerbot 的“狙/其他枪”过滤复用该分类，原许可集合不变。`control/weapon_aim.*` 只从当前不可变快照、当前本地身体的完整 `activeWeapon` 句柄和本批 `weapons[].definition` 解析部位；低位索引相同、重复句柄、缺编号均不认作某个类别。`targets` 与单变量对照的 `comparisons` 共用解析器，掩体判断检查解析后的所选点，并使用原预测时序；所选骨点缺失不以其他部位替代。

按住侧键期间切枪会保持同一目标、自动切换部位，不额外要求松键；旧采集批的待发运动仍由最终 revision 核验拒绝，下一批按当前武器重新求解。手工修改类别设置继续沿用原参数变更清理及松键规则。Rage 的显式 `TargetPoint` 不消费这些手动部位，继续按自己的伤害策略选点；RCS、Reader、固件和 PUBG 参数不改。页面使用默认展开的共享 Disclosure 与名称右侧说明，不恢复运行控制卡。

`cs2AimCoverCheck` 默认关闭。初选按原有优先级在找到可见瞄点的候选人中选择。按住期间继续搜索锁定人物的所选部位。已打包地图的静态掩体用于查询，烟雾、动态门和其他人物超出该数据范围。

`control/static_cover.*` 在后台加载场景，按来源、连接、本地身份及地图撤销旧资源，失败最短间隔 5 秒重试。每轮多个候选点使用同一个当前场景。提交前复查该时刻到已接受点的预测射线。地图、资源或射线状态异常时依据现有状态暂停。Rage 继续使用显式目标和自己的掩体开关。单变量组先按 v1 基线选人，预测几何改变时复核最终射线。

## 实际计算

来源必须是普通本地 Player，相机来源、Local controller/pawn 和人物完整句柄一致。眼角基准与完整当前 AimPunch 求值有效；已核验的普通本地无委托/父变换 source2 输入值不依赖视觉选择器，其余分支仍要求原生 context 存在且一致，原生鼠标横纵导数有限且非零。观战、死亡、未知分支、缺少可信时钟等不能产生输出。

Reader的来源1–7均已求值，不在消费者重复历史插值、父变换或委托。委托元数据只解释基准来源；零句柄保留存在性，来源实体不在人物列表时仍可使用该基准作方向推导，不能换掉所属人物的AimPunch。普通输入分支1–4进入控制；来源5–7的世界角可以预览，但世界方向对局部鼠标的变换尚未核验，因此保持不输出。

初选按 Aim 常规的包含对象筛选队伍，并要求正血量、正常 life-state、非休眠及有效的选定语义骨点。初选点需在当前矩阵视野内，可按三维距离或角差排序，并受可设置的角度和原生距离范围限制。可选静态掩体判断按上述所选部位规则执行。HEAD 使用已核验骨原点。

设读取区间中点映射到本机的年龄为 `a`，手动预计执行延迟为 `d`，则预测窗口为 `h = (a+d)/1000` 秒。默认 `d=20ms` 是公开可修改的模型假设。默认控制样本年龄上限150ms，独立于展示有效期；读取区间及映射不确定度超限时停止。启用速度补偿时：

```text
target = sampledBone + targetWorldVelocity * h
eye    = sampledLocalEye + selfWorldVelocity * h
delta  = target - eye
yaw    = atan2(delta.y, delta.x) * 180/pi
pitch  = -atan2(delta.z, hypot(delta.x, delta.y)) * 180/pi
```

发射参考为 `eye_basis + E(P, simulation+h) + E(U, simulation+h)`；关闭后坐补偿时只使用基准。E 仍按冻结求值器的衰减、速度积分、插值及乘二规则执行。这里明确假设游戏时间等速前进且期间没有新冲量；不能预测未收到的射击、受击、动作或未来指令。数据看板的 E 继续只在 Reader 声明的本批游戏时刻求值，不与预测混淆。

所需角减发射参考得到 Pitch/Yaw 误差，Yaw 使用最短差值。相机0.45倍反馈、独立 view-punch、渲染矩阵和跟随后坐准星都不作为额外发射补偿；矩阵不重复叠加反馈。没有自动开火、散布、PUBG 的子弹下坠或归零模型。

Reader 的 `yaw/pitch_degrees_per_delta` 已包含轴向符号、灵敏度、纵轴和当前开镜倍率。原生公式明确采用 `kx=ky=1` 的直接输入链路假设；这不是实测证据。实测模式使用已采用的 `kx/ky = nativeDelta/deviceCount`，于是：

```text
yawDegreesPerCount   = readerYawDerivative   * kx
pitchDegreesPerCount = readerPitchDerivative * ky
countX = yawError   / yawDegreesPerCount
countY = pitchError / pitchDegreesPerCount
```

每轴速度、步长、间隔与XY预算采用握手能力和稳定速度档位比例。加减速、停止距离、小数余量与已启用学习模型约束作用于运动。待采样反映的已发角度先从误差扣除；按预计响应延迟核销，它是模型而非 ACK。持续发出足够角度但输入角度超过500ms不变时停止，避免无反馈追赶。空闲时不反复发送 STOP。

## 按住与停止

按住时锁定完整 controller/pawn。人物短暂缺帧仅暂停同人，恢复后继续；CS2 具有正式 health/alive/life-state，明确死亡后本次按住不选另一个人。松开再按可重选。此策略没有改动 PUBG 的既有缺帧/死亡规则。

native_context是本批原生查询选择器，会在-1/0/1正常切换；普通本地无父/委托source2不依赖该选择器，其他分支仍按当前组匹配。simulation时间可因Controller/世界预测路线切换而回退，即使相同world/context也不承诺跨批单调。每批按自身完整游戏时间与P/U独立求值；采集序号及QPC高水位仍核验，乱序时停止当前输出，可信新帧恢复后继续同一人。

短暂缺组、目标缺帧和调度中断保留完整锁定句柄，不要求松键；不使用旧坐标/角度。设备侧键回传短暂失效立即停止，现有真实松开计数证明没有松键后才恢复；隐藏在一批数据里的松开重按会先终止旧锁定，再开始新意图。设备重新连接、能力变化、会话、参数与真正来源身份变化仍撤销旧资格，先松开再按。

鼠标响应优先观察已核验的普通本地Pawn预测输入角，其次当前Pawn输入角，再到全局输入角，来源明确展示。真实无响应仍停止位移，等待新的实际输入角变化后恢复原目标，不自动试探移动。页面分别展示当前可计算目标和按住期间保留的锁定身份；当前故障恢复后撤销警告，最近一次暂停原因/时间/次数继续可查。没有保留旧几何冒作当前结果。

延迟与平滑的实测边界、15个真实C++控制器离线案例、原生计时及分离扰动通道的后续方案见[后坐抵消延迟方案](CS2_RECOIL_LATENCY_PLAN.md)。本轮只修状态与响应观察，后坐E、倍率、20ms、速度比例与运动数值规则不变。

## 可选的实机校验

原生公式无需先做四向测量。当前固件把命令计数直接加到相对HID报告，软件不再重复乘DPI/灵敏度；从该HID链路到游戏累计输入的1:1按明确假设处理。如果经过输入缩放、转发或效果不符，可做校验并选择实测。切换模式、记录或其他参数仍会结束本次跟随并要求松键；选择实测但无记录不自动回退成公式。旧版已采用的记录迁移时保留实测模式。

在本地离线练习中，保持普通第一人称、视角放平、不射击、不变倍且物理鼠标不动。点击 Aimbot 页“开始设备校准”，先松开，再持续按住所选侧键。每方向以当前原生导数估计约0.5度的小幅输入，4–32设备计数，并始终服从设备能力；四个方向均有新的采样反馈与等待窗口。实际角幅取决于待测映射，不能预先当作物理测量。

校准只依赖原生输入角度、鼠标导数、同一角色/相机身份与可信采样时间，不要求敌人、世界眼部位置、eye_basis或AimPunch。PC2.2.0误用了完整瞄准条件，少数后坐时间/上下文缺失会把0/4直接取消；2.2.1已分离资格、最终提交复核和UI按钮条件。过期、时钟不可信、输入缺失仍停止并保留具体原因。接收快照时先取得锁再读观察时刻，避免将并发新帧/时钟当成“未来”。

按同一来源身份和映射分别比较横纵往返，检查跨轴污染、响应幅度和双向一致性；取消、松键、过期、换上下文或失败不接受部分结果。通过后显示原生增量/设备计数，用户点击“采用并保存”才保存记录并选择实测模式，保存失败不会先切模式。等待窗口不是执行延迟测量；开镜倍率随 Reader 自动变化，无须再乘一次。

记录有格式版本、核验 Build、独立横纵比值、参考导数和等待窗口上界。更换设备、USB 路由、系统输入处理或出现非线性时应重新校准；本机没有可证明物理链路身份的字段，不能自动保证旧记录适用于新链路。配置、模型和所有旧参数在升级时保留，新增键只通过显式的旧文件缺失兼容补充。
