# Triggerbot

PC2.8.12 / 既有固件v7.1。当前只在CS2提供真实功能；其他游戏保留入口并明确显示尚无核验的Hitbox支持。本轮无需重烧固件。

PC2.8.37补充：CS2的Aimbot、Triggerbot、Rage为互斥功能，开启任一项先关闭其他两项；关闭后不自动恢复旧项。独立RCS的既有规则保持。所有Aim子页的H2组纵向排列，Triggerbot说明ⓘ位于其所属标签内部右侧，未选中也可查看，详见[Aim功能选择](AIM_ACTIVATION.md)。

## 检测

`games/cs2/trigger/detection`使用本批已核验的射击视点和`evaluateRecoil.contextDirection`（原生眼角基准加当前P/U射击偏移），不取枪口模型位置、渲染相机或无后坐的屏幕准星。起点依据沿用[射击起点证据](CS2_REMAINING_DAMAGE.md)。执行时刻和内缩判断见 [Triggerbot 执行时刻预测](CS2_TRIGGER_PREDICTION.md)。

资源命中体经当前完整骨世界姿态构造，复用`hitboxes::TargetIntersector`。对有效存活人物求首次交点，由 Aim 常规的包含对象决定首次命中的人物能否触发点击。未包含的人物挡在前面时停止触发。要求明确本地人物、队伍、活跃枪械编号、弹药和非换弹状态。刀、投掷物、C4及未知物品排除。实际命中还取决于穿透、散布和服务器规则。

`trigger::Controller`独立处理有效源身份/校准时钟、最大年龄、观察版本复核、同capture去重和点击节奏；只在当前CS2进程处于本机前台时检测，并在提交前复核。前台事实由Windows适配器注入，算法不依赖Win32。按观察版本缓存一次求交，不逐毫秒重复构造所有命中体。

启用掩体判断时，共享的 StaticCover 按 Reader 来源、连接、进程、人物和地图代次在后台加载静态场景，失败间隔 5 秒重试。场景加载后，检测和提交复核直接查询预测射线到第一个 Hitbox 交点的路径，逐帧复用同一个场景。只有确定路径可见才可点击。显式遮挡、地图未就绪和核验失败各有状态提示。

## 输出

`trigger::OutputProgram`装饰已有Aimbot或RCS程序，完整转发其移动计算、触发键和生命周期。有限按钮效果是`application::ports::OutputProgram/OutputDevice`的独立端口；设备所有者复核会话、当前配置、真实按钮和源版本，使用原SerialSender与有界CommandOutbox。通道忙则拒绝，重新核验后再提议，不累积待发点击。没有第二条串口或UI按键注入。

默认关闭；CS2本机前台时启用后无需侧键。C++按游戏保存以下配置：

| 字段 | 默认值 | 范围/含义 |
| --- | --- | --- |
| cs2TriggerEnabled | false | 启用 |
| cs2TriggerSnipers | true | 允许狙击枪触发 |
| cs2TriggerSniperInaccuracyLimit | 0.004 | 0–1 小数，当前狙击枪完整 Inaccuracy 必须严格小于上限 |
| cs2TriggerOtherGuns | true | 允许其余已支持枪械触发 |
| cs2TriggerIntervalRangeMs | 90–110 ms | 两端均为 50–1000 ms 的整数，决定下一次点击的最小间隔 |
| cs2TriggerHoldRangeMs | 15–25 ms | 两端均为 5–40 ms 的整数，抽样时长进入有限点击报文 |
| cs2TriggerMaxAgeMs | 150 | 20–500ms，采样年龄 |
| cs2HitboxInsetPercent | 10 | 0–90%，Aim → 常规共享的 Hitbox 内缩比例 |
| cs2TriggerTimeOffsetMs | 0 | -100 至 100 ms 整数，命中预测的手动修正值 |
| cs2TriggerCoverCheck | false | 独立静态掩体门禁 |
| cs2TriggerReactionEnabled | false | 掩体判断开启时生效，按各目标的骨点可见性计时 |
| cs2TriggerReactionMs | 0 | 0–5000ms，读取起点至实际逻辑执行的反应时间 |

两项区间分别保存 min、max、distribution，各自在输入框下方选择分布。旧的 min、max 区间补 normal，旧标量继续按既有规则迁移。模式标识由共享契约校验，未知模式和超出范围的端点明确报错。

| distribution | 菜单 | 取值规则 |
| --- | --- | --- |
| normal | 正态分布 | 截断正态，均值为中点，标准差为宽度除以 6，越界重新抽取 |
| uniform | 均匀分布 | 上下限在内的每个整数等概率 |
| triangular | 三角分布 | 以中点为峰值，概率密度向两端线性递减 |
| lower | 偏向下限 | 以最小值为峰值的三角分布，概率密度随取值增大而线性递减 |
| upper | 偏向上限 | 以最大值为峰值的三角分布，概率密度随取值增大而线性递增 |

非均匀模式先抽连续值再四舍五入到整数毫秒。上下限相等时使用固定值并且不消耗随机数。抽样内核位于 src/domain/random_range，包含声明与实现，只依赖标准库和调用方提供的随机数引擎。JSON 校验在 application/settings/random_range，游戏模块只保留时长约束和何时抽样。前端共用区间契约及分布选择控件。

成功提交一次点击后抽取下一次最小间隔，设置编辑保留当前已抽出的冷却。同一次点击重试沿用已抽出的按下时长。修改按下时长的区间或分布会撤销旧提议并重新抽样。物理左键、会话与设备资格、同一采样去重和固件释放沿用现有输出链路。

## 枪械类型

功能开关区域的“启用枪械类型”提供独立的“狙”和“其他枪”开关，两项默认true并按CS2配置保存，旧配置缺字段仍保留原行为。`trigger/weapon_filter.hpp`统一分类和许可；狙为AWP(9)、G3SG1(11)、SCAR-20(38)、SSG 08(40)，类别与[游戏物品配置](https://github.com/SteamDatabase/GameTracking-CS2/blob/master/game/csgo/pak01_dir/scripts/items/items_game.txt)的sniper_rifle一致。本轮核对证据为out/triggerbot-weapons/weapon-source.json。其他枪仅包括原有34项已支持枪械中余下项，不能把刀、投掷物、未支持/未知编号默认当作“其他”。

检测当前本地手持枪械的definition，切枪后自动换类别；关闭类别返回weapon-filtered并撤销待发点击，属于用户选择的正常等待，不报连接故障。两个开关均关闭时不自动点击，主开关、Aimbot/RCS及原命中体/掩体/反应/物理优先等门禁保持独立。说明放在类型标题右侧ⓘ。

PC2.8.43 在「判断条件 → 启用枪械类型」提供狙击枪 Inaccuracy 上限。读取本批当前持枪的完整 Inaccuracy，复用数据看板的模型、原生分支和采样区间核验，并要求 Reader 声明能力、完整拥有者句柄属于本地已验证人物。达到上限或数据不可用时等待下一批。比较使用协议 float 精度。其他枪械沿用原判断条件。

## 逐目标反应时间

反应时间是掩体判断的子项。关闭掩体时停用反应判定并清除当前计时，保留已保存的开关和毫秒值。同时开启后，射击路径须通过静态掩体判断，且该目标须满足反应时间。骨点扫描从本批实际射击视点寻找各目标至少一个可见骨点，和当前瞄点、点击冷却独立。

ReactionMonitor 后台保留一个运行任务、一个可替换待办和最新结果。ReactionTimers 分目标记录首次可见批次的起读时间。全遮挡、不可核验、人物离场或中间已观察帧未分析时撤销连续性。当前全身结果未到时，只允许携带紧邻一次观察的起点，并在当前帧实时复核同一人物此前可见的骨点。复核不过则等待本批扫描。换地图、来源或目标过滤时重新计时。

剩余等待为`max(0, 反应设置 - (逻辑执行时刻 - 首次可见批次的起读时刻))`。起读来自Reader正式时间戳，经当前有效SourceClockEstimate映射到本机单调时钟；以起读而非读完、接收或后台完成作为起点，因此读取、传输、排队、处理已耗时间均计入，小于设置或已超设置时只等剩余或0ms。计时保存源时钟值，校准估计正常刷新不重启；真正失效的映射仍拒绝。使用获取观察之后的observedAtMs避免早于并发新数据的调用时刻。时钟换算有既有不确定度门禁，不能称为精确单向延迟或游戏/USB确认；正常射线、数据年龄、设备、队友优先、去重与冷却条件仍全部保留。

运行计数表示已提交的有限点击请求，不代表USB送达、服务器开火或命中确认。运行原因、请求计数及当前目标/Hitbox集中到顶部页面上下文栏，删除页面内重复状态卡；遵循故障优先、恢复撤销、稳定标识不重复提示。待查掩体/正常遮挡属于预期等待，缺图/场景不可用/未知仍明确提示。

页面的「功能」下提供点击间隔和左键按下时长的上下限，以及采样年龄上限。「判断条件」下的反应时间开关和数值随「掩体判断」展开，遮挡开关关闭后仍显示已保存数值。各有子项的设置可收起，说明位于所属设置右侧的 ⓘ。

## v7.1协议

原24字节v1帧/CRC及运动限制不变（当前目标500000baud、2ms、100计数、预算200）。

| 操作 | 字段与语义 |
| --- | --- |
| Probe 1 | 原EnableToken握手，撤销点击协商；继续回传旧flags，兼容旧PC |
| Probe 3 | EnableToken、sequence=3、dx=16，其余0；新PC请求有限左键能力 |
| feedback bit16 | 仅支持此功能且已协商时回传；没有该位的设备不发送点击 |
| Type5 ButtonPulse | 非零session、sequence=1、intervalMs=5–40，其余0。PC 将本次抽出的时长传给固件 |
| Stop 0 | 撤销待发点击、结束当前按下并请求释放，同时保留原运动停止语义 |

固件`core/control/ButtonPulse`一次只接纳一个动作，待按下请求20ms未提交则过期；按下成功提交USB后开始计时，无需PC再发抬起包。释放在背压下保留并重试，恢复/停止不能丢掉已按下的释放。运动门控与预算耗尽只结束运动，不意外截断点击。

`ReportPipeline`合并真实按钮与自动左键，按钮布局留在profile。Codec缓存原始物理按钮，不把注入态当真实按钮；合成报文不重复真实位移/滚轮。按钮回传及松开计数仍来自物理输入。固定内存与非阻塞USB/UART服务保持，未加Host诊断或恢复旧硬件试验。
