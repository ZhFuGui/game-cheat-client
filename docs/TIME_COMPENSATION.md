# 人物位置的时间补偿

## 当前PC1.1.0：旋转也独立对齐

骨点、相机位置和旋转分别保留源区间，共用`estimateSampleTime`校验；旋转不再借整批完成时间，10～100ms按实龄处理。位置补偿和现有弹道保持。待反映输入、角度外扰与暂估20ms生效参考分开核算，见[角度反馈](ANGULAR_FEEDBACK.md)。实时旋转时钟不可靠时暂停，不借旧命令前缀匹配授予资格。

## 当前PC0.9.1（2026-10-16）

正式接入Reader完整身体世界速度`CharacterMovement.world.velocity`及独立[4]观察，骑乘/基座贡献已计入，不能重复加。实时不再使用组件速度+父对象假定0。骨点与相机分别用自己的源区间、各自原点和可靠时钟对齐，XYZ统一cm后换SI。用户已明确选择相机作为弹道起点，不使用枪口几何或时间；枪口缺失、变化和CLEAR不影响计算。原生组件字段保留独立诊断，旧录制不被授予弹道资格。

`P_now=P_sample+V×age`的年龄/误差边界保持250/25ms、速度采样差100ms、探测3000ms。800ms源进展和类别配对不是允许无限外推。缺速/失败/时钟不合格时，几何选择可展示原始点，但生产弹道暂停，不能退回未补偿输出。合法完整零速度可用。

对齐至当前后才求飞行期间提前量；补偿虚拟视线点不再做第二次年龄预测或旧骨点差分。下一20ms决策重新求解前馈，与子弹飞行时间不同。自己的速度只对齐相机及下一决策起点，不给已飞行子弹加自速。相机用View位置字段的独立时间；不借用类别头部或枪口时间。详见[BALLISTIC_RUNTIME.md](BALLISTIC_RUNTIME.md)及[新契约](READER_CONTRACT_20261016.md)。远端升级/实际吞吐另行验收。

## 历史PC0.5.6（原有验证范围）

PC0.5.6，2026-10-13。用户最新要求直接启用，载具和其他附着对象造成的额外速度暂按0。使用 Reader 原生 `CharacterMovement.velocity`，应用层标记 `NativeComponentAssumingZeroParent`，不将它写成上游已核实的身体总世界速度。没有新增远程模块，也无需为这项PC功能再次烧录盒子。

对当前选定部位计算 `P_now = P_sample + V × age_seconds`，XYZ均使用世界轴和相同的游戏单位。T1采用该部位骨架组真实 `source_sample` 的中点，保留读取区间；T2为本机实际控制计算时间。全帧开始时间只是外层采集窗口，不能代替每个部位实际读取时刻。速度还保留自己本批的采样区间及人物完整生命周期身份。

通过同一Living连接的四时间戳探测，以Reader接收/发送中点与消费者发送/接收中点估计时钟偏移；先依正式映射将Reader QPC转为其单调时间，再映射至本机QPC毫秒域。不同机器的原始QPC不能相减。净RTT/2仅用作网络不对称的不确定度，再加Reader映射误差、本机1ms量化及骨架读取区间半宽；这不是精确单程延迟测量。源码先对整数源时间求差，再转浮点，避免Windows长时间原点造成精度丢失。

当前预测边界：探测最多3秒旧，估计不确定度最多25ms，骨架/速度采样差最多100ms，估计年龄加不确定度最多250ms。较小负年龄在误差范围内取0，明显未来或超限数据不预测。它们只限制外推；已有Reader配对/源进展规则和用户设置的采样差保持原样。不能把0.8秒业务数据容忍理解为允许恒速预测0.8秒。

每次计算都从不可变的Reader原始部位重新预测一次，目标资格/角度比较和输出规划使用同一入口，不把补偿结果再补偿。成功时用原生速度求局部角速度供S轨迹前馈，不另加旧25ms规划前瞻。缺速、失败、生命周期不符、时钟失效时返回当前原始部位，不能沿用旧速度或按缓存继续推；零向量立即取消移动前馈。新契约已订阅速度时不改用旧位置差分速度。松侧键、缺帧暂停与恢复原人物的既有逻辑保持。

界面“时间补偿”行显示是否生效、估计数据年龄及不确定度，并标明“载具/附着速度暂按0”。此契约增加严格字段21；Reader服务端须升级至支持该字段的版本，旧严格解码器不能直接接收新Hello。此次本机同步和离线兼容通过不等于远端已更新，亦未自动操作远端。
