# 鼠标移动调试

## PC1.2.1：前台原生批量采集

接收 Raw Input 的专用 C++ 线程现在位于拥有 Electron 窗口的进程内，由 `mousebox-input.node` 装配。旧版本界面在前台、接收器在独立后台进程；Windows 会对后台 Raw Input 限速和合并，最近两次用户记录中约8ms的中位间隔与该机制吻合。这是改造依据，不能在未实测前断言已经恢复1000Hz。

新接收器只在本应用前台且活动区域有效时注册，保留浏览器正常光标和按钮消息。先读取已被消息循环取出的当前记录，再用 `GetRawInputBuffer` 批量读取仍在队列内的记录；当前记录不重复计数，批次内逐条保留。批次接收时间仍是程序实际观察时间，不插值还原所谓USB时间戳。开始时保存本进程已有鼠标注册；结束后仅在本接收器仍持有注册时恢复它，不覆盖后来发生的 Chromium 注册。空闲时不注册鼠标、不限制光标，也不开资格检查计时器。

学习完整分段和结束后的报文通过私有 C++ 二进制管道交给原后台运行时分析，原始记录不进入 JavaScript、不进入既有Web展示桥；进度仍沿用有界状态更新。管道核验服务端PID、客户端父进程和可执行文件，并拒绝远程连接；帧、完成队列和超时均有上限。停止命令等待此前完成数据被原生运行时接收，避免“立即拟合”漏掉最后一段。会话撤销、主进程失去响应导致的租约超时、关闭和断流仍停止采集并恢复本功能持有的光标范围。

统计始终为 **实际接收条数 / 实际经过秒数**，保留静止时间，不添加倍增系数、不补造记录、也不将1000Hz设为目标值。缓冲区在订阅输入之前准备，先排空上一场残留，再以本次注册之前的单调时钟为起点；不在已经收到输入后重置统计分母。原始CSV和原有统计格式保持；结果属于Windows接收流，不能声明为逐USB传输量测。本改造不安装驱动、不要求CA证书或测试签名、不改固件和Reader。

构建由现有 `mousebox-native.vcxproj` 同时生成 EXE 和稳定 Node-API v8 模块，正式仍只有两个VS项目。`--startup-report` 和隐藏发布验收记录采集端实际PID、方法和未采集状态。自动检查仅使用合成缓冲区、二进制通道以及无有效活动区时的拒绝启动；真实回报率、前台采集和焦点行为仍由用户手测。

PC1.1.12 起，侧栏底部“鼠标移动调试”紧邻“运行日志”上方，包含“速度学习”和“鼠标特征”。旧速度学习的采集、拟合、验证、模型和文件功能保留，旧 `/learning` 与 `--learning` 导航进入新入口的速度学习子页；`--mouse-characteristics` 可直接进入鼠标特征。

PC1.1.13 修复再次开始后立即提示“活动区域改变，已结束”：隐藏上次统计会让滚动条消失、活动区变宽；页面已固定滚动条占位。启动时先移除旧统计并完成滚动位置调整，等待原生端确认最终区域，再请求采集；请求失败恢复旧结果，等待区域确认期间切页则撤销启动。真实区域移动、失焦、遮挡等结束条件保留。

## 鼠标特征使用

在本机前台活动区域点击“开始特征采集”，自由移动连接本机的鼠标，点击区域内“结束采集”或按 Esc 结束。第一只产生相对移动的设备被锁定，随后该设备的零位移/按键报文也保留，其他设备单独计数、不混合；绝对坐标输入单独计数、不换算成鼠标计数。开始前来自未锁定设备的零位移事件不计入该设备样本。

采集没有秒数限制，由用户决定结束时刻。完整原始记录最多200万条，达到容量后自动结束并统计。失焦、最小化、切页、活动区域移动/不完整可见、弹窗遮挡、会话撤销与退出均结束采集并恢复本功能持有的光标范围。保留原有光标限制的所有权核验，不覆盖其他程序后来施加的限制。鼠标特征模式保留正常光标及按钮消息，结束按钮位于活动区域内。

此调试子功能无需 Reader 或盒子连接，不新增/请求 Reader 字段、不更新固件，也不驱动鼠标输出。开始采集时暂停原生输出模式，关闭 F8 测试；结束后沿用现有松侧键再按的资格规则。速度学习与特征采集互斥，特征数据不进入速度训练或模型。

## 统计口径

来源为 [Windows Raw Input / RAWMOUSE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawmouse)，每个接收到的相对鼠标事件保留 `lLastX/lLastY`、原生单调时钟微秒接收时间、移动标志和按钮变化标志。该接口与 USB 总线抓包不同，操作系统允许合并移动事件。没有逐 USB 报文保证，也不以此声称物理回报率已测得1000Hz。

- 原始计数不按 DPI、屏幕像素或游戏灵敏度重新缩放。
- 单报文总计数为 `hypot(dx, dy)`，X/Y 分布保留正负方向。
- 不重采样、不插值、不合并采集记录、不补造静止报文或初始零点。
- 报文总数包含已锁定设备的零位移事件；非零/零位移数量分别显示。
- P50/P95/P99 使用全部记录的总计数、最近秩定义；缺失样本用 null，不伪造0。
- 相邻接收时间差有 N−1 份；同微秒内收到多份时保留零间隔并单独统计数量。
- 全程平均接收率为 N / 从开始到结束的时长，包含停顿。它和间隔分布都受系统调度影响，不作为 USB 回报率结论。
- 显示每轴绝对值最大值、总计数分位和峰值、间隔中位数/P95；完整 JSON 另保留净位移、累计计数、间隔最大值等。

## 图表与保存

结束后在原生后台线程分析，再向 Web 发送有界结果：每种分布最多64箱，时间图最多512段。时间段保留每轴/总计数的最小值、最大值和平均值；空段使用 null，绘图不跨空段连线，单个大位移峰值不会被均值隐藏。可在总计数、X轴、Y轴之间切换；另有接收间隔分布。悬停分布查看区间，展开分布明细查看数量与占比；时间图支持鼠标悬停和方向键查看。

全部原始记录保留在 C++，不逐报文进入 JS；采集中仅推送进度，完整结果按需读取一次。CSV 与统计 JSON 自动保存至 `%LOCALAPPDATA%\Mousebox\mouse-debug\reports-*.csv` 与相邻 `.csv.json`；隔离 `--data-dir` 使用自己的子目录。CSV 字段为 `t_us,dx,dy,flags,button_flags`，时间原点为本次采集开始。界面的“导出原始报文”使用受限文件选择接口导出 CSV。清空当前结果仅清内存，保留保存文件；切换页面仍可返回当前运行期间的最后结果。

所有计算、文件保存与统计在原生实现，前端只接收进度和图表摘要。Reader 协议、实时控制和无固定 FPS 上限的 DirectX 链路保持原有职责。

## 验证范围

回归覆盖无数据/真实零、正负轴/大值、同时间戳/长空段、完整分布数量、时间图峰值、有限摘要、CSV原始字段、原生统计与TypeScript契约互验、互斥及停止、侧栏/子页/图表/导出交互。自动检查使用合成输入，不注册真实采集、限制桌面光标或注入鼠标；实际设备采集、失焦/跨屏与回报率由用户手动验收。

1.1.13 增加区域确认与启动先后顺序、失败恢复、卸载取消检查；隐藏 Electron 使用合成状态检查三个窗口尺寸下的结果/采集切换及大计数进度，另通过真实 React 启动处理器、拦截原生开始命令，验证滚动后重新开始的布局稳定。该流程没有进行真实 Raw Input 采集。

## 控制输出上限与原始采集

原PC1.2.2/v5的最快档为 `16 × 1000 / 5 = 3200` 计数/秒。PC1.2.3/v6目标改为每轴 `100 × 1000 / 2 = 50000` 计数/秒，TTL500000波特率、最多500次控制/秒，五档同步调整，详见[控制链路](CONTROL_LINK.md)。这是控制上限，不是实测频率或特征采集上限；实际输出还受加减速、目标误差及发送背压影响。原始特征采集保留Windows给出的int32 dx/dy，不套用±100或50000的限制。

这些仍是软件策略与自定义固件上限，不是HID字段或硬件的实测极限。PC与固件必须配套；新版检查v6能力，旧设备不会被误当作已支持新上限。完整的频率和物理透传验收需在实际烧录后进行。
